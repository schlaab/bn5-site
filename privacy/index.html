Inbox-bridge-mcp Privacy Policy

Effective date: November 26, 2026. This policy covers the Inbox-bridge-mcp application (OAuth client "Inbox-bridge-mcp"), operated by bn5.me. Contact: mail@bn5.me. Home page: bn5.me.

1. What Inbox-bridge-mcp is

Inbox-bridge-mcp is a private, single-operator application that runs on its operator's own computer. It reads the operator's Gmail and Google Calendar across several Google accounts that the operator owns, or whose owners have explicitly authorized it, and presents them in one place: a daily summary of unread mail and upcoming events, search across the accounts, and the text of a specific thread when asked. It is not offered to the public, has no sign-up and has no other users.

2. Google user data we access, and why

Permission (scope)Data accessedWhy
gmail.readonlyMessage headers (sender, recipients, subject, date), labels, snippets, message bodies and attachmentsTo list unread mail, search mail, show a thread the operator asks for, and save an attachment the operator asks for
calendar.readonlyThe list of calendars and their events (time, title, location, attendee count, the operator's response)To show today's and tomorrow's schedule across the accounts
gmail.modify (only on two accounts the operator owns)The same as gmail.readonly, plus the ability to change labels and read state and to create draftsTo apply a label, mark a message read, or save a reply as a draft, each only when the operator asks. The application never sends, trashes or deletes mail, even though this permission would allow it.

We also receive the email address of each connected account, to tell the accounts apart. We do not access contacts, Drive files or any other Google data.

3. How the data is used

Google user data is used only to provide the features in section 1 to the operator, for the accounts the operator connected. It is not used for advertising, is not sold, is not used to build user profiles, and is not used to develop, improve or train generalized artificial intelligence or machine learning models.

4. How the data is stored and protected

  • OAuth tokens are stored in the macOS Keychain on the operator's computer, protected by the operator's login password.
  • Mail and calendar data are fetched on demand and held in memory for at most 30 seconds as a cache. They are not written to a database.
  • Attachments are saved only when the operator asks, in a private folder on the operator's computer, and deleted after 30 days.
  • A local log records which tool ran, for which account, and the message or thread identifiers involved. It does not contain message content.
  • Nothing is stored on any server operated by Inbox-bridge-mcp; there is none. Data travels between Google and the operator's computer over HTTPS.

5. Sharing

Google user data is not sold, rented or transferred to third parties, data brokers or advertising services. The single exception is that the operator uses an AI assistant (Anthropic's Claude) on his own behalf to read and summarize his own mail and calendar; excerpts of the operator's own data pass to that assistant only when the operator asks it to. Data may also be disclosed if required by law. No person other than the operator reads the data, except as required by law or with the account owner's consent.

6. Retention and deletion

Cached mail and calendar data expire within 30 seconds; saved attachments are deleted after 30 days; the local log is rotated at 10 MB. OAuth tokens are kept until access is revoked. Any account owner can revoke access at any time from myaccount.google.com/permissions, which stops all access immediately. To have the token and any locally stored data for an account deleted, email mail@bn5.me; it will be deleted within 30 days.

7. Limited Use disclosure

Inbox-bridge-mcp's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. In particular, Inbox-bridge-mcp uses Google user data only to provide the user-facing features described above; does not transfer it except as described in section 5; does not use it for advertising; does not allow humans to read it except as described in section 5; and does not use it to train AI or machine learning models.

8. Children

Inbox-bridge-mcp is not directed to children and is not used with accounts of children under 13.
